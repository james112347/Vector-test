<task type="auto">
  <name>Task 2: Create check-in reminder system with browser push notifications</name>
  <files>src/lib/checkin-reminders.ts, src/pages/Dashboard.tsx</files>
  <action>
    Create `src/lib/checkin-reminders.ts` with a `scheduleCheckinReminders(userId: number)` function that:

    1. Calls `analyzeHabitPatterns(userId)` from `../lib/habit-intelligence` to get the user's habit patterns.
    2. Calls `getOrientationPreferences(userId)` from `../lib/energy-orientation/notification-manager` to check if notifications are enabled and get quiet hours.
    3. If notifications are disabled or permission not granted, return early.
    4. For each pattern with regularity 'very_regular' or 'regular', check if any typicalTime is within the next 60 minutes but not in the past (comparing current time with typicalTimes).
    5. For upcoming times, use `setTimeout` to schedule a call to `sendNotification()` from `../lib/notifications` at the right moment. The notification should:
       - Title: use the same TYPE_LABELS mapping from habit-intelligence (duplicate the map or export it)
       - Body: contextual message like "Di solito a quest'ora registri {type}. Tocca per aprire Vector."
       - Tag: `checkin-reminder-{type}` (prevents duplicates)
       - navigateTo: '/Vector-test/' (opens dashboard)
    6. Check quiet hours via the `isQuietHours` logic (implement a local check or import — since `isQuietHours` is not exported from notification-manager, implement it locally: parse quietHours.start and quietHours.end, compare with current time, handle overnight spans).
    7. Store the last reminder check timestamp in localStorage key `vector_last_reminder_check` to avoid re-scheduling on rapid re-renders (debounce: skip if checked within last 10 minutes).
    8. Return the count of scheduled reminders.

    Also export the TYPE_LABELS map from `src/lib/habit-intelligence.ts` — change `const TYPE_LABELS` to `export const TYPE_LABELS`.

    In `src/pages/Dashboard.tsx`, call `scheduleCheckinReminders(user.id)` inside the existing `loadData` callback (after data loads successfully), so reminders are evaluated on each app open and foreground return. Import the function at the top.

    Do NOT use service worker periodic sync (browser support is too limited and unreliable). The setTimeout approach works well because:
    - It fires while the app is open (which is when we can send notifications)
    - The service worker already handles notification clicks for background delivery
    - Re-scheduling happens on each app open via the Dashboard loadData
  </action>
  <verify>

  </verify>

  </done>
